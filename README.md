# ระบบจัดการสต๊อกแร็ค OEM (QR Scan In/Out)

ระบบสต๊อกสำหรับร้านซ่อมรถ รองรับ:
- สแกน QR Code เพื่อ **รับเข้า** และ **จ่ายออก** แร็ค OEM จากสต็อก
- ก่อนจ่ายออก ระบบจะ**เตือน แสดงชื่อรุ่น + รหัสรุ่น + จำนวนคงเหลือ** ให้ช่างตรวจสอบก่อนกดยืนยันเสมอ
- ระบบผู้ใช้ 2 สิทธิ์ (role):
  - **ออฟฟิส (office)** — เพิ่ม/แก้ไข/ลบ/ดูรายการแร็ค (CRUD เต็มรูปแบบ), ดูประวัติรายการ, พิมพ์ QR Code, จัดการบัญชีผู้ใช้
  - **ช่าง (technician)** — สแกน QR เพื่อรับเข้า/จ่ายออกได้เท่านั้น ไม่สามารถแก้ไขรายการแร็คได้
- ฐานข้อมูล SQL ผ่าน **MySQL ของ XAMPP** (ใช้ phpMyAdmin ดูข้อมูลได้ตามปกติ)

## โครงสร้างโปรเจกต์

```
stock-system/
├── backend/      Node.js + Express + MySQL (เชื่อมต่อ XAMPP) (REST API)
└── frontend/     React (เว็บแอป สำหรับออฟฟิสและช่าง)
```

## ฐานข้อมูล (MySQL ผ่าน XAMPP)

ตาราง 3 ตัวหลัก ระบบจะ**สร้างฐานข้อมูลและตารางให้อัตโนมัติ**ตอนรันเซิร์ฟเวอร์ครั้งแรก (ไม่ต้องไปสร้างเองใน phpMyAdmin):

- **users** — username, password (เข้ารหัส bcrypt), full_name, role (`office` หรือ `technician`)
- **racks** — model_code (รหัสรุ่น เช่น `RTTO5201`), name (รายการแร็ค OEM), stock_qty (สต็อกเหลือ), min_stock (จุดแจ้งเตือนสต็อกต่ำ)
- **transactions** — ประวัติรับเข้า/จ่ายออกทุกรายการ พร้อมผู้ทำรายการและเวลา

ข้อมูลตัวอย่างที่ใส่ไว้ให้แล้ว (seed ครั้งแรกที่รัน):
- รหัสรุ่น `RTTO5201` — แร็ค Toyota Corolla AE100 AE112 ปี 1991-2000 — สต็อกเหลือ 2
- ผู้ใช้เริ่มต้น: `admin` / `admin123` (ออฟฟิส), `tech1` / `tech123` (ช่าง) — **เปลี่ยนรหัสผ่านทันทีหลังติดตั้งจริง**

## วิธีติดตั้งและรัน

### 0. เปิด XAMPP และสตาร์ท MySQL

เปิด **XAMPP Control Panel** แล้วกด **Start** ที่บรรทัด **MySQL** (ไม่จำเป็นต้องสตาร์ท Apache ก็ได้ เพราะ Node.js เสิร์ฟหน้าเว็บเอง — สตาร์ท Apache ไว้ด้วยก็ได้ถ้าอยากเปิด phpMyAdmin ดูข้อมูล)

ค่าเริ่มต้นของ XAMPP คือ: host `localhost`, พอร์ต `3306`, user `root`, ไม่มีรหัสผ่าน — ระบบตั้งค่านี้ไว้ให้แล้วใน `.env.example`

### 1. ติดตั้ง Backend

```bash
cd backend
npm install
copy .env.example .env
```

ถ้า MySQL ของ XAMPP คุณตั้งรหัสผ่าน root ไว้ หรือเปลี่ยนพอร์ต ให้แก้ไฟล์ `backend\.env` ตรงนี้ให้ตรงกับเครื่องคุณ:

```
DB_HOST=localhost
DB_PORT=3306
DB_USER=root
DB_PASSWORD=
DB_NAME=stock_system
```

### 2. สร้าง SSL Certificate (จำเป็นสำหรับกล้องสแกน QR บนมือถือ)

มือถือจะอนุญาตให้เว็บเข้าถึงกล้อง (getUserMedia) เฉพาะผ่าน **HTTPS** เท่านั้น จึงต้องสร้าง self-signed certificate ไว้ที่ `backend/certs/`:

```bash
mkdir certs
openssl req -x509 -newkey rsa:2048 -keyout certs/key.pem -out certs/cert.pem -days 365 -nodes -subj "/CN=localhost"
```

> บน Windows ถ้าไม่มีคำสั่ง `openssl` ต้องติดตั้ง OpenSSL ก่อนและเพิ่ม path ไปยังโฟลเดอร์ `bin` ของ OpenSSL ลงใน System PATH แล้วเปิด terminal ใหม่

### 3. หาค่า IP ของคอมพิวเตอร์ในวง WiFi

```bash
ipconfig        # Windows: ดูที่ "IPv4 Address" เช่น 192.168.1.50
```

### 4. Build และรัน Frontend

```bash
cd ../frontend
npm install
cp .env.example .env
```

แก้ไฟล์ `frontend/.env` ให้ชี้ไป IP จริงของคอมพิวเตอร์ (ไม่ใช่ localhost) เพื่อให้มือถือเรียก API ได้:

```
VITE_API_URL=https://192.168.1.50:4443/api
```

จากนั้น build:

```bash
npm run build
```

ไฟล์ที่ build แล้วจะถูก Express ฝั่ง backend เสิร์ฟให้อัตโนมัติ (ดูใน `backend/server.js`)

### 5. รัน Backend (เสิร์ฟทั้ง API และหน้าเว็บ)

```bash
cd ../backend
npm start
```

จะเห็น log:
```
HTTP server: http://localhost:4000
HTTPS server: https://localhost:4443
```

### 6. เข้าใช้งาน

- **บนคอมพิวเตอร์ (ออฟฟิส):** เปิด `https://localhost:4443` (ครั้งแรกเบราว์เซอร์จะเตือนเรื่อง certificate ไม่น่าเชื่อถือ ให้กด "ดำเนินการต่อ/Advanced > Proceed" เนื่องจากเป็น self-signed certificate)
- **บนมือถือของช่าง (ผ่าน WiFi เดียวกัน):** เปิด `https://<IP คอมพิวเตอร์>:4443` เช่น `https://192.168.1.50:4443` แล้วกดยอมรับ certificate เช่นกัน จากนั้น login ด้วยบัญชีช่าง

## วิธีใช้งานระบบสแกน QR

1. ออฟฟิส เพิ่มรายการแร็คใหม่ในหน้า "รายการแร็ค (CRUD)" → กดปุ่ม **QR Code** เพื่อดูและพิมพ์ QR (เนื้อหา QR คือรหัสรุ่น เช่น `RTTO5201`) ไปติดที่ตัวแร็คหรือช่องเก็บ
2. ช่าง เปิดหน้า "สแกน QR" เลือกโหมด **รับเข้าสต็อก** หรือ **จ่ายออกจากสต็อก**
3. สแกน QR ที่ติดอยู่บนแร็ค ระบบจะค้นหารหัสรุ่นและแสดงกล่องยืนยัน บอก **ชื่อรุ่น, รหัสรุ่น, สต็อกคงเหลือ** ให้ตรวจสอบก่อนเสมอ (กรณีจ่ายออกจะมีกรอบสีแดงเตือนเป็นพิเศษ)
4. ใส่จำนวน แล้วกดยืนยัน ระบบจะอัปเดตสต็อกและบันทึกประวัติอัตโนมัติ
5. ถ้าสต็อกไม่พอ (จ่ายออกมากกว่าที่มี) ระบบจะปฏิเสธคำขอและแจ้งจำนวนคงเหลือจริง

## ความปลอดภัย / สิ่งที่ควรทำก่อนใช้งานจริง

- เปลี่ยนรหัสผ่าน `admin` และ `tech1` ทันที (ที่หน้า "จัดการผู้ใช้" — เพิ่ม endpoint `/api/users` ให้ใช้แล้ว แนะนำเพิ่มหน้า UI จัดการผู้ใช้เพิ่มเติมหากต้องการ)
- เปลี่ยนค่า `JWT_SECRET` ใน `backend/.env` เป็นค่าสุ่มที่คาดเดาไม่ได้
- ฐานข้อมูลอยู่ที่ `backend/data/stock.db` ควร backup ไฟล์นี้เป็นระยะ

## หมายเหตุทางเทคนิค

- Backend ใช้ `mysql2` เชื่อมต่อ MySQL ของ XAMPP โดยตรง — ตอนรันเซิร์ฟเวอร์ครั้งแรกจะรันคำสั่ง `CREATE DATABASE IF NOT EXISTS` และสร้างตารางอัตโนมัติ ไม่ต้องไปสร้างเองใน phpMyAdmin (แต่เปิด phpMyAdmin ดูข้อมูลได้ตามปกติ ที่ `http://localhost/phpmyadmin`)
- ถ้าต้องการสร้าง database/ตารางแยกโดยไม่ต้องรันเซิร์ฟเวอร์ ใช้คำสั่ง `npm run init-db` ในโฟลเดอร์ backend ได้เลย
- Frontend ใช้ `html5-qrcode` อ่าน QR จากกล้องมือถือ
- การยืนยัน OUT ทำที่ทั้ง frontend (popup เตือน) และ backend (เช็คสต็อกไม่ให้ติดลบ พร้อม lock แถวด้วย `FOR UPDATE` ระหว่างทำรายการ เพื่อป้องกันข้อมูลพังถ้ามีการสแกนพร้อมกันจากหลายเครื่อง) เพื่อความปลอดภัยของข้อมูล
